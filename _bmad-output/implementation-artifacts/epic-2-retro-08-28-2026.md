## Findings

### Aggregate view — spec-to-implementation reconciliation

- **F1 — Stories 2.4 & 2.5 never ran the review loop; frontmatter says `in-progress`.** `spec-2-4-*.md` and `spec-2-5-*.md` carry `status: 'in-progress'`, `followup_review_recommended: false`, and have **no** `## Review Triage Log` or `## Auto Run Result` sections — unlike the other 7 stories. They were committed as pre-session WIP (`b00e9c8`). `sprint-status.yaml` marks both `done`. *Source:* `spec-2-4-incidentdetail-approvalbanner.md:4`, `spec-2-5-executiontrace-viewer.md:4`; commit `b00e9c8`. **Disposition: fix now** (reconcile status + run an adversarial pass). *Upstream lesson:* an epic run should not silently absorb externally-authored WIP without subjecting it to the same gate as loop-built stories.

- **F2 — The integrated Live Console is unbuilt and unowned.** Every story from 2.1 onward defers "the real Live Console layout, the polling wiring (`useIncidents` / `useApproval`), and the router" to "later stories." No Epic 2 story closes it. `App.tsx` is explicitly "NOT a real layout": it wires the static `allIncidents` fixture into components and stubs `onApprovalAction`. `useIncidents` / `useApproval` (built in 2.3 / 2.4) are never imported by `App.tsx`. *Source:* `frontend/src/App.tsx:12-25` (shell comment), `App.tsx` imports; `grep useIncidents frontend/src/App.tsx` → no match. **Disposition: fix now** (action item). *Upstream lesson:* a deferral repeated by every story with no story owning the closure is an epic-planning gap — the integrating story should be in the epic.

- **F3 — The entire frontend ↔ backend seam is unexercised.** `backend/` has no HTTP server (`grep -rn 'FastAPI|APIRouter|uvicorn|flask' backend/` → nothing). The four `client.ts` functions (`fetchIncidents`, `postApproval`, `fetchQuery`, `postKillSwitch`) are built to the `ARCHITECTURE-SPINE.md` contract (lines 225-231) and tested only against `vi.stubGlobal('fetch', …)`. No end-to-end path from a rendered control to a real response exists. *Source:* `backend/` file listing; `client.test.ts`; `ARCHITECTURE-SPINE.md:225-231`. **Disposition: fix now** (action item; overlaps epic-1 retro item 4 "Commit Epic 1.5-1.13 backend work"). *Upstream lesson:* a frontend epic against a contract with no server implementation carries integration risk that no amount of unit coverage retires.

### Aggregate view — pattern divergence / design-system gaps

- **F4 — No muted-text token; secondary text uses `opacity: 0.6` on `--text` in ≥5 components.** Deferred independently in Story 2.3 (feed title, stale line, empty line, status line, confidence reason) and Story 2.7 (the load-bearing "not live AIS" disclaimer). `tokens.css` defines no `--text-muted` / `--text-secondary`. WCAG AA (4.5:1) risk on text that includes safety-relevant copy. *Source:* `spec-2-3-incidentfeed.md` deferred[0], `spec-2-7-mappanel.md` deferred[0]; `tokens.css:11-77`. **Disposition: defer → action item** (design-system change, not a one-component fix).

- **F5 — Story 2.1's token set has no type-size ramp; every later story hardcodes `font-size`.** `tokens.css` exposes `--font-size-micro-label` (11px), `--font-size-incident-title`, `--font-size-confidence` — no body / label / caption size token. Result: a "bare literal `font-size`" review patch finding recurred in **2.6, 2.7, 2.8, and 2.9**. *Source:* `tokens.css:71-76`; Review Triage Logs of `spec-2-6`…`spec-2-9`. **Disposition: fix now** (extend the token set). *Upstream lesson:* the foundational token story under-scoped the ramp; the cost was paid four times downstream.

- **F6 — Barrel `export default` inconsistency across component folders.** Flagged low in 2.7, 2.8, and 2.9 (`index.ts` re-exports `default` for one component but not its sibling in the same folder). Fixed per-story on request; no convention prevents the next one. *Source:* Review Triage Logs `spec-2-7`/`spec-2-8`/`spec-2-9`. **Disposition: accept** (each instance fixed) + *upstream lesson:* add a one-line barrel convention to the frontend AGENTS/context.

- **F7 — Archive rows show "Auto-resolved" for every resolved incident via reused `statusPhrase`.** `IncidentArchiveList` reuses `IncidentRow`, whose status line comes from `statusPhrase` (returns "Auto-resolved" for any `status:'resolved'`). The Approved / Rejected distinction lives only in the sibling outcome tag. A screen-reader user on the row button hears "…Auto-resolved" even for an approved incident (mitigated in 2.9 by the added `aria-describedby` → outcome tag). *Source:* `lib/incident.ts:51-62`; `spec-2-9` Design Notes + Review Triage Log. **Disposition: accept-as-is** (spec-chosen: row reused verbatim, tag carries the distinction) — recorded so future retros don't re-flag.

### Aggregate view — verification / process

- **F8 — `followup_review_recommended: true` on 7 of 9 stories.** 2.1, 2.2, 2.3, 2.6, 2.7, 2.8, 2.9 all tripped it — every case on low-severity *volume* (`3×medium + 1×low ≥ 5`), none on a high-severity patch. The accumulated items are real but individually trivial (hover/active states, focus management on route/selection change, `role="group"` labelling, i18n indirection, barrel consistency). *Source:* frontmatter of all 9 specs. **Disposition: defer → single consolidated UI-polish pass** rather than 7 per-story follow-ups. *Upstream lesson:* the heuristic is miscalibrated for greenfield UI, where a story legitimately generates 8–10 low-severity a11y/CSS refinements.

- **F9 — `oversized` spec warning on 6 of 9 stories.** 2.3, 2.4, 2.5, 2.6, 2.8, 2.9 exceeded the 1600-token target. UI stories carry heavy contract detail (exact token names, ARIA attributes, verbatim microcopy, I/O matrices). *Source:* `warnings: [oversized]` in six spec frontmatters. **Disposition: accept** + *upstream lesson:* raise the target for UI epics or push more detail into the Code Map.

- **F10 — Only one test mounts `<App/>`.** Integration coverage arrived only with Story 2.9's `App.test.tsx` (route swap). Stories 2.1–2.8 have zero test that composes the app; every earlier review noted this and routed it out of scope as "the shell is a throwaway." 495 tests, but the composition point is barely covered. *Source:* `find frontend/src -name '*.test.*'`; `App.test.tsx` (new in `7c7321d`). **Disposition: subsumed by F2** — the integration story brings real `<App/>` coverage.
