## Findings

### F1 — `POLICY_START` trace stage is not in the canonical `STAGES` enum (minor, fix now)
- **Source:** `backend/orchestrator/run.py:207` appends `append_trace(incident, "POLICY_START", ...)`; `backend/orchestrator/trace.py:18-29` defines `STAGES` as `("INGEST","CORRELATE","AGENT_CALL","SYNTHESIZE","CONFIDENCE","POLICY_DECISION","DG_CHECK","APPROVAL","EXECUTE","VERIFY")` — no `"POLICY_START"`.
- **Impact:** every incident's trace carries a stage label outside the documented canonical set (Story 1.12). Consumers validating `entry.stage in STAGES` would reject a legit entry, or the label is silently orphaned.
- **Disposition:** fix now — add `"POLICY_START"` to `STAGES` (or rename the trace stage to `"POLICY_DECISION"`); owner: backend.

### F2 — Kill switch does not guard the Tier 3 human-approve path (safety gap, fix now / spec reconcile)
- **Source:** `backend/orchestrator/run.py:284-299` — `approve_incident` only blocks when `incident.blocked_by_kill_switch` is already `True`. That flag is set **only** inside `_execute_selected` (`run.py:152-160`), i.e. the Tier 1/2 auto-execute path. A pure Tier 3 hold (`selected` set, `tier==3`, never auto-executed) reaches `approve_incident` with `blocked_by_kill_switch=False`, so it proceeds to execute **even while the global kill switch is engaged**. Contrast with `backend/policy/killswitch.py` docstring ("operator engagement ... blocks execution").
- **Impact:** Story 1.10's stated intent — global kill switch halts execution — is not honored for the highest-risk (Tier 3, human-approval) incidents on the approve path. Auto-execute (1/2) is guarded; human-approve (3) is not.
- **Disposition:** fix now — re-check `is_kill_switch_engaged()` at the top of `approve_incident` and return `{approved: False, reason: "kill switch engaged"}` when engaged; owner: backend/safety. Reconcile with `epics.md` Story 1.10 acceptance.

### F3 — Test suite encodes as-built behavior; two intended safety behaviors are unimplemented (process lesson / spec reconciliation)
- **Source:** `backend/tests/orchestrator/test_epic1.py:275-278` assert `"CONFIDENCE"/"POLICY_DECISION"/"DG_CHECK"/"APPROVAL" in STAGES` (the original `POLICY_START` assertion was removed); `:352` and `:390` assert `execution_results == []` + `blocked_by_kill_switch is True` on approve — i.e. the suite was **corrected to match the current code**, not the spec.
- **Impact:** the green suite verifies *current* behavior. Two specified behaviors — a `POLICY_START` stage and "kill switch blocks approval" — are absent from the implementation yet the tests were bent to pass. This is exactly the divergence F1/F2 describe, now locked in by tests.
- **Disposition:** spec reconciliation — decide (PM/architect) whether F1/F2 are required; if yes, fix code and re-assert the original intent in tests; if no, update `epics.md` Story 1.10/1.12 so the spec matches reality. Owner: PM + backend.

### F4 — Epic 1.5–1.13 are uncommitted (process lesson)
