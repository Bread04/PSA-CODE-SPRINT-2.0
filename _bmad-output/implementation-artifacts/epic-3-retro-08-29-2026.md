## Findings

### F1 — Proof-not-enforcement is the epic's defining pattern, and it is a demo caveat (accepted, recorded)

All three delivered stories ship a **mock or pure helper plus a test that proves it integrates**, with no wire-in to the running pipeline:

- **3.2** — `backend/agents/yard_load_balancing.py:68` `should_offer_pasir_panjang()` has no production caller. The live pipeline's reroute decision is still the LLM yard specialist's, unprompted by the helper. *Source:* `spec-3-2-*.md` Residual risks ("Proof, not enforcement"); `grep should_offer_pasir_panjang backend/` → only the helper, its tests, and `demo_seed`.
- **3.4** — `mpa_clearance` is a registered mock service (`backend/mock_services/services.py:110`) but nothing in `run.py` calls it; the proof drives it via a test-only `_option_to_action` monkeypatch. *Source:* `spec-3-4-*.md` Residual risks ("Proof, not enforcement (epics.md AC divergence)"); `run.py` byte-unchanged.
- **3.3 / 3.5** — descoped precisely because wiring a real 4th specialist would touch the frozen contract.

Each individual choice is correct and spec-sanctioned (Epic 1 golden path frozen after Day 3; `models/recovery.py` is `extra="forbid"`). But the **aggregate** effect is that Epic 3's judging claim — "the architecture generalizes rather than being hardcoded for one incident shape" — is demonstrated by the **test suite**, not by anything a judge can trigger live. `epics.md` Story 3.4's ACs are even phrased as running-pipeline behaviour ("a mocked clearance-check mock service ... is called"), which the delivery does not do. The `demo-load-balancing` seed incident (`backend/api/demo_seed.py`) is a static fixture, not a live pipeline run.
**Disposition: accept** (no code change — the freeze is the right call this close to demo) **+ action item**: brief the demo narration so the "generalizes" claim is framed as "proven by our concurrency + extensibility test suite" and the Pasir Panjang / MPA pieces are described as designed-and-proven integration points, not live behaviour. *Upstream lesson:* a stretch epic whose FRs are written as runtime behaviour ("is called", "affects an option") but whose implementation rule is "strictly additive, don't touch the frozen path" has a built-in AC-to-delivery gap; name the proof-vs-enforcement split at epic-planning time.

### F2 — FR20 + FR18 descoped: contract-freeze vs stretch-scope collision (accepted via SCP, recorded)

Stories 3.3 and 3.5 each read "reuse the specialist pattern exactly" yet both require a 4th roster entry, and the roster is pinned in five places: `SpecialistBundle` `min_length=3, max_length=3` (`backend/agents/base.py:97-99`), `AgentName` 3-value `Literal` (`base.py:60`), arbiter guard `len != 3` (`backend/agents/arbiter.py:217`), `dispatch._AGENT_ORDER` 3-tuple (`dispatch.py:37`), and `test_specialists.py::test_bundle_requires_exactly_three_recommendations` + `len(fake.calls) == 3` assertions. `bmad-build-auto` correctly HALTed both rather than editing a frozen contract unattended.
**Disposition: resolved** via `sprint-change-proposal-2026-08-29.md` — cut both, close Epic 3, preserve the conditional-4th-specialist design (6-step unfreeze sketch) in `deferred-work.md`. *Upstream lesson:* when minting an "additive" story (FR20 was minted during epic decomposition on 2026-08-27), run a pre-flight check of what frozen contracts its stated approach would touch — "reuse the pattern" and "extend the roster" are not the same additivity.

### F3 — `FakeAsyncAnthropic` test double now copy-pasted across 3 test modules (carried forward, worse)

`test_arbiter.py`, `test_specialists.py`, and the new `test_load_balancing.py` each carry a near-identical `_Block` / `_Response` / `_Messages` / `FakeAsyncAnthropic` / `_text_response` copy. Any change to the injected client shape needs three synchronized edits. Pre-existing (2 copies), pushed to 3 by Story 3.2. *Source:* `spec-3-2-*.md` frontmatter `deferred[0]`; `grep -rl "class FakeAsyncAnthropic" backend/tests/` → 3 files, confirmed this retro.
**Disposition: defer → action item** — extract to `backend/tests/_fakes.py` (or a `conftest` fixture). Low severity; do it before the next test module needs a 4th copy.

### F4 — Threshold constants have no architecture backing (accepted, recorded)

`TUAS_HIGH_THRESHOLD = 0.85` and `PASIR_PANJANG_HEADROOM_CEILING = 0.70` (`backend/agents/yard_load_balancing.py:26-28`) are commented "Demo-tuned, no AD backing". They only ever gate a proof test and a seed fixture, so the risk is contained — but if F1's action item ever wires the helper in, these numbers become live policy with no traceable rationale. *Source:* review patch finding in `spec-3-2-*.md` Review Triage Log.
**Disposition: accept** while the helper is proof-only; fold a rationale (or an AD reference) into any future wire-in.

### F5 — Concurrency proof is genuinely non-vacuous (win, recorded)

Story 3.1's review caught and fixed a vacuous isolation assertion (`_assert_isolated` now checks `entity_refs` containment and owning-`incident_id` equality, not just non-equality), a Barrier-hang risk (wrapped in `asyncio.wait_for(30)`), and a kill-switch global-state bleed (added a reset+re-run assertion). Story 3.2 explicitly mirrored the anti-vacuous framing — the Pasir Panjang option's presence is driven by the real `should_offer_pasir_panjang` gate run over HIGH and LOW payloads with identical responder logic, not a hard-coded canned string. *Source:* `spec-3-1-*.md` Review Triage Log; `spec-3-2-*.md` Design Notes.
This is the core Epic 3 deliverable and it is solid: 4 deterministic isolation tests + 38 load-balancing tests, all green on repeat.
