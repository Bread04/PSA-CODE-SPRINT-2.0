## Findings

### F1 — Two independent trace-stage → display-state mappings, built one commit apart, that disagree on `POLICY_START` (low)

Epic 4 folds the backend `STAGES` vocabulary into a display state **twice**, in two files, with no shared source:

- `frontend/src/components/GeoMapPanel/GeoMapPanel.tsx:43` `stageToStateKey()` — maps a trace entry's `stage` to one of 6 marker states. It handles `POLICY_DECISION` but **not** `POLICY_START`; an entry with `stage: "POLICY_START"` falls through to `default: return 'pending'`.
- `frontend/src/lib/stageRail.ts:46-50` `RAIL_STAGES` — the `POLICY_DECISION` rail stage explicitly folds **both** `['POLICY_START', 'POLICY_DECISION']`.

`backend/orchestrator/run.py:256` emits `POLICY_START` (added by epic-1-retro action item 1). So if the 2–3s poll lands in the window where the selected incident's **latest** trace entry is `POLICY_START`, the Strait Map markers read "pending" while the Stage Rail correctly shows `POLICY_DECISION` active — the two panels disagree on screen.
*Source:* `GeoMapPanel.tsx:43-65` vs `stageRail.ts:46-50`; `run.py:256`; `trace.py:27`.
**Disposition: fix now (small) → action item.** Add `case 'POLICY_START':` alongside `'POLICY_DECISION'` in `stageToStateKey` (→ `'deciding'`). One line + a test. Impact today is transient and cosmetic (no data error, resolves on the next poll), which is why it is low, not medium.

### F2 — The stage-mapping logic is duplicated in principle, not just this one case (low, upstream lesson)

`stageToStateKey` (6 marker states: pending/analysing/deciding/applied/blocked/done) and `deriveRail` (10 `RAIL_STAGES` × 5 rail states) are two hand-maintained projections of the same `backend/orchestrator/trace.py` `STAGES` tuple. Any future `STAGES` change — a new stage, a rename — needs two synchronized frontend edits, and F1 is the first instance of them drifting. This is the Epic 4 analogue of the Epic 3 `FakeAsyncAnthropic` triplication (`epic-3-retro` F3).
*Source:* the two files above; `epic-4-context.md` ("Derived only from trace entries").
**Disposition: defer → action item.** Not worth a shared abstraction for two consumers today; do record a one-line note in the frontend context that both `GeoMapPanel.stageToStateKey` and `stageRail.RAIL_STAGES` must be updated together when `STAGES` changes.

### F3 — Responsible-AI constraint met, and test-pinned (win, recorded)

The hard constraint from `epic-4-context.md` — "must never imply an AIS / VTS / vessel-tracking capability" — is delivered well:

- Caption honesty is carried verbatim from the superseded Story 2.7 and test-pinned: the caption contains "illustrative" and "not live AIS" and must not contain "real-time" / "live positions" / "tracking" / "current location". *Source:* `GeoMapPanel.tsx:199-202`; `epic-4-context.md` "Caption honesty (load-bearing, test-pinned)".
- The `aria-label` also states "Positions are mock incident state, not live AIS." (`GeoMapPanel.tsx:159-163`).
- Zero runtime network: `lib/geo.ts:24` `import worldAtlas from 'world-atlas/countries-50m.json'` is a bundled static import, decoded once at module scope; `epic-4-context.md` says this is asserted with a `fetch` spy in tests.
- Marker movement is discrete state from the trace (`markerState` reads the last trace entry's stage), never interpolated positions.
- Colour is never the sole signal — every marker carries a `<text>` label + kind-specific shape; every rail stage carries a state word + optional `ERROR`/`RETRY`/`FALLBACK` flag + a shape glyph.

### F4 — Degraded-safe fallback verified (win, recorded)

`GeoMapPanel` with no incident returns `<MapPanel variant="strait" />` (`GeoMapPanel.tsx:134-136`) — Story 2.7's schematic is retained, not reverted, exactly as `epic-4-context.md` requires. `StageRail` with no incident renders every stage `pending` (`deriveRail` on an empty/nullish trace). No error state on the empty path.

### F5 — Three new frontend dependencies (accepted, recorded)

`d3-geo`, `topojson-client`, `world-atlas` (+ `topojson-specification` / `geojson` types) added; the bundled `countries-50m.json` atlas is ~100 KB (spec estimate; `epic-4-context.md`). Spec-sanctioned (Leaflet/Mapbox explicitly ruled out for demo-safety and a11y). `geo.ts:132-145` degrades to no basemap on a decode failure and to the full country list if the id-filter (`STRAIT_LAND_IDS`) ever returns empty — defensive.
**Disposition: accept.** Note the bundle-size delta exists; acceptable for a demo build.
