PSA Code Sprint · 4 people · 6-day build

One incident, one pipeline, one writer.

Portwatch is a multi-agent orchestration layer for Tuas Port. It detects and correlates cross-system disruptions no single system sees end to end, analyses them with scoped specialist agents, auto-executes what is provably safe, escalates what is not, and leaves a complete auditable trace of every decision.

02 — Design paradigm

The LLM proposes. The deterministic engine disposes.

Every incident runs as an isolated async task — an actor — that owns exactly one mutable Incident record with an embedded append-only trace. Work flows through fixed pipeline stages, fanning out to parallel specialist agents at analysis and fanning back in at synthesis. No stage other than the orchestrator ever writes shared state; everything else is called and returns data.

The proposal half

Specialist agents (berth, crane, yard) and the arbiter recommend. They call the Anthropic Messages API directly, each with a static, scoped tool manifest — never a broader autonomous-agent surface.

The decision half

Tier classification, the DG/IMDG gate, the confidence formula, and the kill switch are plain deterministic code with no model call in the decision path. This is the direct architectural answer to the "black-box AI" objection — it holds everywhere, not only where convenient.

03 — The pipeline

Ingest to verify, with fan-out at analysis

The orchestrator is the sole writer (AD-4). Specialist calls run concurrently (AD-13). The DG gate sits at a fixed position after policy classification and before execution, independent of tier (AD-8); a conflict loops back to the arbiter, capped at two re-plans. The kill switch gates exactly one point — immediately before any mock-service execution (AD-7). The dashboard only ever reads, by polling one endpoint every 2–3s (AD-6).

Solid arrows: data flow. Dashed amber: DG re-plan loop-back (AD-8). Dotted red: kill-switch gate (AD-7). The read-only API and dashboard are a projection of the same Incident record — never a second write path.

    07 — Positions held

    Safety, security, scale

    ConcernPosition
    Kill switchGlobal flag, single enforcement point immediately pre-execution (AD-7). A Tier 1/2 decision blocked by it is trace-marked and flagged on the incident, never silently dropped or reclassified (AD-15).
    Policy authorityTier engine, DG gate and confidence formula are plain deterministic functions — no LLM in the decision path.
    Least privilegeStatic per-agent tool manifests (AD-3); berth's manifest cannot contain the yard-manager schema — the model can't call what it was never given.
    DG / IMDG complianceSimplified, representative ruleset for demo purposes — explicitly not a certified compliance implementation (stated, so it reads as intentional scoping).
    Concurrency proof≥2 incidents resolved concurrently via stateless-per-incident tasks (AD-1, AD-4); asserted at the orchestrator layer by 4 deterministic isolation tests + an asyncio.Barrier simultaneity harness — non-vacuous, not wall-clock-dependent.
    Demo mock overridesPer-agent MOCK_AGENTS map (AD-16) plus a recorded-backup run. A canned response is always trace-marked mock_forced: true and takes the same missing-data confidence penalty as a fallback — never passed off as real.
    Map surfaceRead-only projection of the same poll; basemap vendored into the bundle, zero runtime tile calls (AD-17). Not a decision surface.
    Approval bottleneck at scaleNamed, not built. Future answer: prioritise by predicted-impact / SLA-risk, batch by shared root cause.

    09 — Stack & deferred

    What it's built on, and what it isn't

    LayerChoice
    BackendPython 3.12+ floor · FastAPI ~0.141.x · single deployable process, all lanes as modules (AD-1)
    Agent callsAnthropic Messages API, direct — not Agent SDK / Tool Runner / Managed Agents (AD-2) · claude-sonnet-5 for all agent calls
    FrontendReact 19.2.8 · TypeScript 5.x · Vite 8.1.3 · Harbor Signal tokens (Space Grotesk + IBM Plex Mono, marine ink, seafoam / amber / red signals)
    PersistenceIn-memory only — no database; state lost on restart, acceptable for a demo session (AD-9)
    AuthNone — single fixed operator context (AD-10)
    DeploymentLocal dev machines for the build; one instance for the live demo. No containers, no cloud infra. Production strategy deferred.

    Deferred, with reason

    • Production deployment / infra (containers, cloud, HA) — not needed for a 6-day demo.
    • Approval-bottleneck-at-scale — named future work, not built.
    • Real PSA system integrations — mocked services only for this build.
    • Certified DG / legal compliance — simplified representative ruleset, stated explicitly.
    • FR20 (AGV/Gate specialist) + FR18 (weather circuit-breaker) — descoped 2026-08-29. Both need a 4th roster entry, which cannot be added without unfreezing the Day-3-frozen SpecialistBundle / arbiter contract. Lowest-ranked Day-5 stretch items; conditional-4th-specialist design preserved in deferred-work.md.
    • Strait-level collision avoidance, transshipment MARL / GNN optimisation — named in the PRD as roadmap-only, excluded from this spine entirely.
