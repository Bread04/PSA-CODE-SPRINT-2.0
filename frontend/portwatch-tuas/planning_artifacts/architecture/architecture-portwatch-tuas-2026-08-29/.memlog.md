# Architecture memlog

- type: decision | text: "Paradigm: Human-in-the-loop operations co-pilot with bounded autonomy and visible decision trace. The product is a control-plane for disruption handling, not a full autonomous terminal controller."
- type: decision | text: "Binds: operational objective detection, recommendation ranking, approval gating, and execution trace. Prevents: silent autonomous actions and opaque black-box behavior."
- type: decision | text: "Stack: Vite + React + TypeScript client, Express server, shared types/constants. This matches the existing project scaffold and keeps a lightweight demo-ready system boundary."
- type: decision | text: "Major boundaries: UI/operations surface, orchestration layer, event-normalization and objective engine, decision engine, execution/audit log. Prevents: mixing policy, UI state, and operational data mutation in one layer."
- type: decision | text: "State model: each disruption creates a decision record containing objective, evidence, option set, confidence, required approval tier, and execution outcome. Prevents: fragmented state across screens and duplicated truth."
- type: decision | text: "Approval model: Tier 1 actions remain auto-allowed only within pre-authorized safety bounds; Tier 2 requires visible notification; Tier 3 requires explicit operator approval before execution."
- type: decision | text: "Operational contract: all actions are expressed as plain-language proposals with trade-offs, assumptions, and missing-data warnings. Prevents: unexplained or jargon-heavy recommendations."
- type: constraint | text: "Brownfield constraint: leverage the current codebase conventions already present in the Vite React app and Express server, rather than introducing a parallel stack or framework."
- type: constraint | text: "Project goal: the system must be explainable and demo-friendly for PSA Code Sprint 2.0, emphasizing clear reasoning and operator trust over full automation."
- type: assumption | text: "The prototype is a single-terminal disruption workflow, not a full enterprise integration layer."
- type: question | text: "Should the final demo include a live backend reasoning simulation or stay mostly front-end with a scripted decision engine?"
- type: event | text: "Architecture spine initialized for Portwatch-Tuas with focus on disruption response control-plane and human approval gates."
